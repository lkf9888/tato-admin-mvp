先定主体

决定后面所有步骤

注册小程序时选个人还是企业，决定了消息点开之后能看到什么。这个选完就很难改，所以放在最前面。

企业主体

功能完整

  • 需要营业执照
  • 可以用 web-view，消息能点进 /staff-share 页面
  • 要配业务域名（多一步校验文件）

个人主体

够用但受限

  • 不需要营业执照，注册最快
  • 订阅消息照常能发
  • 不能用 web-view——详情页只能看中枢存的那几个字段

选个人主体的话，pages/webview 那个页面就是死的，员工看不到任务详情页、也传不了照片。业务上能不能接受，现在就要想清楚。

订阅消息本身不需要认证就能用。认证主要影响的是部分高级能力和搜索展示——先按不认证跑通，需要了再补。具体以公众平台后台当时显示的为准。

01

注册与域名

微信公众平台

mp.weixin.qq.com → 注册 → 小程序。形如 wx1a2b3c4d5e6f7890。

开发管理 → 开发设置 → 开发者 ID。只显示一次，关掉就要重置。直接贴进密码管理器，下一阶段要填到 Railway。

开发管理 → 开发设置 → 服务器域名，三项都加 https://tatocar.co：

request 合法域名——小程序所有接口调用都走它，不配全都失败。
uploadFile / downloadFile——老任务页传照片、看附件要用。

加 tatocar.co，下载校验文件传到服务器根目录，再点校验。这是 web-view 能打开详情页的前提。个人主体跳过这步。

02

订阅消息模板

微信公众平台

模板决定消息长什么样。字段编号是微信分配的，不一定跟下面的例子一样——以后台实际显示为准，中枢那边按实际编号配。

功能 → 订阅消息 → 公共模板库，挑一个任务/待办类的模板。需要的五个字段：任务内容、时间、车辆、状态、备注。

模板 ID 是一长串。字段编号形如：

thing1   任务内容
time2    到期时间
thing3   车辆信息
phrase4  任务状态
thing5   备注

中枢按字段名推长度限制，所以类型不能记错：phrase 只收 5 个字，thing 收 20 个，character_string 收 32 位。超了微信会整条退回 47003，不是截断。

03

环境变量

Railway 
WECHAT_MINIPROGRAM_APP_ID=wx...
WECHAT_MINIPROGRAM_APP_SECRET=...
NOTIFY_HUB_SESSION_SECRET=// 随机长字符串
WECHAT_TASK_TEMPLATE_ID=// 老任务页还在用

NOTIFY_HUB_SESSION_SECRET 不设会回落到 SESSION_SECRET，但生产环境两个都没有会直接抛错。

不设 NOTIFY_TIMEZONE 会回落到 CSV_IMPORT_TIMEZONE，再不设是 America/Vancouver。绝不能用服务器本地时区——Railway 跑在 UTC，会让每条提醒差七八个小时，而且看起来完全正常。

这个只在测试时指向假服务器用。留空才会走 api.weixin.qq.com。

已经没有代码在读它了。字段映射现在归中枢的 NotifyTemplate.fieldMap 管，见下一阶段。

04

初始化中枢

终端

按顺序跑，后面的命令依赖前面建出来的记录。 

npm run notify-hub -- mini-program:add \
  --app-id wx1a2b3c4d5e6f7890 \
  --name "Ops"

密钥不存数据库，只记变量名，默认就是 WECHAT_MINIPROGRAM_APP_SECRET。

npm run notify-hub -- template:set \
  --mini-program wx1a2b3c4d5e6f7890 \
  --key task \
  --template-id <模板ID> \
  --fields '{"title":"thing1","due":"time2",
             "vehicle":"thing3","action":"phrase4",
             "details":"thing5"}'

左边是调用方用的逻辑名，右边是阶段 02 抄下来的真实编号。

npm run notify-hub -- app:add \
  --key tato --name "TATO" \
  --mini-program wx1a2b3c4d5e6f7890

--key tato 要跟 NOTIFY_APP_KEY 对上（默认就是 tato）。

npm run notify-hub -- tato:sync

给每个在职员工建一个频道。额度不会回填——没人做过的授权造不出来。

npm run notify-hub -- status

密钥那行要显示 ✓ present。显示 ✗ MISSING 就是 Railway 变量没生效，重新部署一次。

05

小程序发布

微信开发者工具

用微信开发者工具打开 wechat-miniprogram/，把 project.config.json 里的 wx-your-app-id 改成真的。

app.js 里的 apiBaseUrl 应该是 https://tatocar.co，和阶段 01 配的 request 合法域名一致。

模拟器发不出订阅消息，必须用真机预览。顺序：打开小程序 → 输绑定码 → 授权提醒 → 让 admin 派个任务 → 微信里收到。

审核前先把体验版跑通。

miniprogram_state 决定消息能发到哪种版本的小程序。审核通过前是体验版，要设 trial，否则消息发不到；发布之后切回 formal。

npm run notify-hub -- mini-program:set \
  --app-id wx1a2b3c4d5e6f7890 --state trial

这不是环境变量。以前是 WECHAT_MINIPROGRAM_STATE，现在是 NotifyMiniProgram 上的一列，没有代码再读那个变量了——设了不生效。

06

交给员工

排班页

排班页展开员工卡片的「Code / 员工备注」，点绑定码就复制。

打开小程序 → 添加频道 → 输码。一个人可以加多个频道，以后接 HostHub 和洗车系统就是再给一个码。

这一步最容易漏，也最要紧。微信一次授权只够收一条消息。勾了这个框，以后每次打开小程序会静默补额度——这是余额能自动恢复的唯一办法。不勾就得每次手动点。

派完回排班页看那一行：应该显示「N 人已绑定 · 还能收 N 条」。显示红字就是额度用完了。

额度是这套系统的核心约束

微信的一次性订阅是「一次授权换一条消息」，授权可以累积，但服务端查不到余额。所以中枢自己记账：员工每次授权上报一次，发送成功扣一格，收到 43101 就清零。

三个地方都会显示余额：排班页那一行、小程序首页的横幅、以及发送接口按订阅者返回的 no_quota。哪个都别忽略——「收不到」以前是静默的，现在不是了。

⚑

收不到消息时对照

errcode
errcode意思怎么办
43101 用户没有未使用的授权了 正常现象。让员工打开小程序重新授权，并勾上「总是保持以上选择」
47003 字段超长或格式不对 多半是 phrase 超了 5 个字。检查阶段 02 记的字段类型
41030 page 路径不对 小程序没发布，或者 pages/message/index 不在 app.json 里
40001 access_token 失效 中枢用的是 stable_token，正常不该出现。真出现了检查 AppSecret 是不是被重置过
40003 openid 不合法 该 openid 属于别的小程序。换过 appid 的话员工要重新绑定
— 完全没反应 先跑 status 看密钥在不在，再看 MINI_PROGRAM_SECRET_MISSING 有没有出现在日志里

勾选状态会自动保存，换设备打开也在。
