# 真机验证清单

到目前为止所有东西验的都是**逻辑、失败路径和模拟器**。相机、AR、相册、上传，
一行都没在真机上跑过。这份清单是把那道门推开。

> **如果只做一件事**，做 §B1：真机拍一张，把文件拷回电脑，跑
> `npx tsx scripts/check-inspection-evidence.ts <文件>`。
> 这一条过了，整条证据链才算真的通；不过，后面全部白搭。

---

## A. 在电脑前（不用车，20 分钟）

### A1. 装到手机上 —— 先别走 TestFlight

第一次验证**直接从 Xcode 跑到自己手机上**。TestFlight 是给员工铺开用的，
每次构建要等审核排队，改一行等十分钟，验不动。

```bash
cd inspection-ios-app && xcodegen generate && open Walkaround.xcodeproj
```

Xcode 里：选 target → Signing & Capabilities → 勾 Automatically manage signing →
Team 选你的开发者账号。`co.tatocar.evidence` 这个 Bundle ID 还没注册过，
Xcode 会自己去建。插上手机，选它当运行目标，⌘R。

- [ ] App 装上了，打开就是相机

⚠️ 真机第一次跑会弹「不受信任的开发者」——手机上
设置 → 通用 → VPN与设备管理 → 信任你的开发者证书。

### A2. 权限文案

App 打开就是相机 —— 没有首页、没有表单。权限弹窗会依次出现。

- [ ] 相机权限文案是中文/英文里说得通的话，不是占位符
- [ ] 定位权限说的是「照片要记录位置，保险理赔会拒收没有位置的照片」
- [ ] 相册权限（到交单页导出时才弹）

### A3. 界面 —— 照着 iPhone 自带相机做的

不用教员工怎么用：快门、镜头切换、点一下对焦、左下角缩略图，位置和系统相机一样。

```
┌──────────────────────────────┐
│  🔦      12 张 · 72%      ⚙  │  ← 手电筒 / 已拍数 · 绕车角度 / 设置
├──────────────────────────────┤
│ (环)                         │  ← 绕车角度环，你永远在最下面
│        ╭──────────╮          │
│        │ 镂空线稿  │          │  ← 这一步要拍的东西
│        ╰──────────╯          │
│   四条轮胎 · 轮毂要拍全 · 3/4  │
│     「往你右边走，那边还没拍」   │  ← 只在绕车那步、有话可说时出现
├──────────────────────────────┤
│           .5  (1×)           │  ← 镜头，选中的是黄色
│    ‹  ●●●◉○○○○○○○  ›         │  ← 11 步，箭头随便跳
│  [缩略图]     (◉)      完成   │  ← 拍了第一张就有「完成」
└──────────────────────────────┘
```

- [ ] 点一下取景框：黄色对焦框出现，然后淡掉
- [ ] 点 .5 / 1× 能切镜头，切完画面没有冻住
- [ ] 取景框是 4:3，上下有黑边 —— **屏幕里看到的就是文件里的**，没有被裁掉的部分
- [ ] 按快门：画面黑闪一下 + 震动一下，左下角缩略图换成刚拍的那张
- [ ] **拍成功不再弹窗**（原来每张都要点「继续」，现在什么都不弹）
- [ ] 拍糊了才弹 —— 一条黑色横条压在取景框下沿，5 秒后自己消失
- [ ] 连糊 3 张后，横条上出现「仍然使用」

## B. 停车场，一台车，一次跑完（60–90 分钟）

停车场这一趟很贵，别分两次。下面每一条都要**当场记下来**，
回电脑前再看就想不起细节了。

### B1. ⭐ 证据链 —— 唯一真正要紧的一条

随便拍一张（哪一格都行）。然后把文件拿回电脑：

**取文件：最省事的办法是让 App 自己传过来**

手机和 Mac 连同一个 WiFi，Mac 上 `npm run dev`，App 的「上传设置」填
`http://<Mac 的局域网 IP>:3000` 和工号。拍满一批交单后点「传一份到后台」，
文件就直接落在 `data/uploads/inspections/<批次>/` 里了。

> 这条路需要拍够 **15 张外观 + 8 张车内** —— 那是 Turo 的地板，
> 「完成」按钮在够之前根本不出现（故意的）。
> 对着自己的车随便拍满就行，第一次验的是文件本身，不是构图。

只想拍一张就验的话，走 Xcode：Window → Devices and Simulators → 选手机 →
Walkaround → 齿轮 → Download Container → 右键「显示包内容」→
`AppData/Library/Application Support/sessions/<批次>/photos/`

```bash
npx tsx scripts/check-inspection-evidence.ts ~/Downloads/front-1.jpg
```

要看到：

- [ ] `capture` 有值，带时区（形如 `2026:09:19 14:03:21 -07:00`）
- [ ] `location` 有经纬度，不是 `-`
- [ ] `camera` 是 `Apple iPhone 1X Pro`
- [ ] 三条 `PASS`

拍完点「完成」，在交单页上看「元数据写入」那一行：

- [ ] 显示「相机直接写入 N 张」，不是「N 直接 · M 补写」

> 换回原生相机之后，这一条**又回到最初的样子**：元数据由 AVFoundation 在出片时写进去，
> 每张应该都是「相机直接写入」（`writtenAtCapture`）。ARKit 那几版的照片是
> `encodedFromCameraPixels`，混在历史记录里是正常的。
>
> 出现「补写」说明 AVFoundation 没写进去、走了 `ExifStamper` 回退。
> **少数几张不算坏**（回退路径是无损的、有测试的），
> 但如果**每一张**都在回退，主路径在这个 iOS 版本上是失效的，要查。

**还要确认没拿到占位图**（iOS 17+ 的 deferred photo proxy）：

- [ ] 文件大小是 1MB 以上的量级，不是几十 KB
- [ ] 用「预览」打开是完整清晰的照片，不是糊的缩略图

### B2. ⚠️ 量一下一次绕车到底多大

默认 1200 万像素（相机自己出的 JPEG），设置里可以开 4800 万。预计 1200 万单张 2.5–4MB、
4800 万单张大约是它的四倍。一次完整计划是 41 张。
**两种都要真的量一遍**：这个数决定生产那个卷撑不撑得住，而它已经满过两次。

拍满 24 张，然后：

- [ ] 单张多少 MB？________
- [ ] 一个批次总共多少 MB？________

> 算笔账：如果单张 8MB，一次绕车就是 **190MB**；一单行程交车+还车两次 = **400MB**；
> 一天十单就是 **4GB/天**。
>
> `lib/uploads.ts` 的注释里写着，他们的 Railway 卷**已经被填满过一次，网站挂了**。
>
> 如果数字大得离谱，就把 `EvidenceCamera` 里的 `maxPhotoDimensions` 从"最大"
> 改成 1200 万像素 —— 存证要的是看得清刮痕，不是数毛。Turo 官方 App 拍的也就这个量级。
> **这个决定要基于量出来的数字，不是猜。**

### B3. 清晰度闸 —— 现在只能看行为，不能定阈值

- [ ] 故意晃着拍一张 → 弹「糊了」，能重拍
- [ ] 好好拍一张 → 直接过
- [ ] 连拍 3 张糊的 → 出现「仍然使用」
- [ ] 点了「仍然使用」→ 交单页「交单前要知道的事」里出现「手动放行」

⚠️ **别在这一步调阈值。** `ImageQualityThresholds.provisional` 里的数是占位的，
要靠 §E 的样本标定。这里只确认闸门本身在工作。

### B3a. 手电筒（原来的闪光灯）

点一下常亮,不是每张闪一次。

- [ ] 点左上角灯的图标 → **立刻亮起来并且一直亮**,图标变黄
- [ ] 再点一下 → 灭
- [ ] 亮着的时候拍照,**快门没有变慢、没有预闪**
- [ ] ⭐ 亮着灯切换 .5 / 1× → **灯还亮着**（换镜头系统会关灯，相机应该马上重新点亮）
- [ ] 按 Home 退到后台 → **灯灭了**（掏出手机看一眼灯有没有还亮着）
- [ ] 回到 App → 灯是灭的,按钮也显示灭（不自动恢复,这是故意的）
- [ ] 杀掉 App → 灯灭

⚠️ 顺便记一下:**开着灯连拍 20 张,手机烫不烫?** ________
> 手电筒是持续耗电和发热的。过热到一定程度硬件会拒绝点亮,
> 那时屏幕上会出现「手电筒打不开 —— 多半是手机太热了」。
> 如果冬天在户外拍 20 张就触发了,说明亮度要往下调。

### B3b. ⭐ 快门防抖闸 —— 最容易把效率毁掉的一个功能

手晃的时候快门圆圈变灰、按不下去。**这一条要验的不是「它会不会拦」,
而是「它会不会烦人」。**

- [ ] 故意晃手机 → 快门圈变灰
- [ ] 手停下 → **几乎立刻**就能按(实测 30–70ms,感觉应该是"没有等待")
- [ ] 正常持机、呼吸、轻微手抖 → **全程都是白的,不该变灰**
- [ ] 连拍 10 张,每次按下去都有反应,**没有一次按了没反应**

⚠️ **最重要的一条:**

- [ ] **快速连按 10 次,统计有几次按了没拍成** ________ 次

> 按快门这个动作本身会晃手机。如果闸门反应太快,会在手指落下和点击生效之间
> 把按钮禁用掉 —— **吃掉的正是它想保护的那张照片**。代码里上升时间常数
> (85ms)特意比下降(30ms)慢得多来防这个,但只有真手指能证明。
> 如果这个数不是 0,告诉我,我把 `SteadinessGate.riseWindow` 再调钝。

- [ ] 戴手套 / 单手举过头顶拍车顶时,快门是不是经常灰着?________

> 举手过头拍车顶本来就不稳,这是最可能被误伤的场景。如果车顶那几张变得很难拍,
> 这个闸门就需要在举高时放宽。

### B4. 定位

- [ ] 室外：黄条「定位未就绪」几秒后消失
- [ ] 关掉定位权限再拍一张 → 照片**照样存下来**，交单页标「缺位置」
- [ ] 地下车库（如果有）：黄条一直在，但能继续拍完

### B4b. 出门前先看一眼方向传感器（10 秒）

右上角齿轮 →「绕车」→「方向传感器」。**对着任何东西都行，不用车。**

- [ ] 写的是「正常 · 朝 N°」
- [ ] 原地慢慢转身，N 跟着变（转一圈大约走完 0–360）

> 写「还没读到」就把手机竖起来对着前方；写「这台手机没有」就不用往下测绕车了。

### B5. ⭐ 绕车角度 —— 这一版换掉了整套判据

不再用 ARKit/LiDAR 找车，改成陀螺仪记录每张照片朝哪个方向拍。**它只提示，不拦任何东西。**

- [ ] 拍了第一张外观之后，左上角出现一个**环**（不是车形图）
- [ ] 绕着车一边走一边拍，环一格一格变绿
- [ ] **环跟着你转：「你」那个白点永远在最下面**
- [ ] ⭐ 环上灰的那段在右边时，底下那行字说的是「往你右边走」；在左边时说「往你左边走」
  —— **这一条最重要**，方向要是反的，整条提示就是在误导人
- [ ] 绕满一圈之后环基本全绿，百分比在 90% 以上
- [ ] 站在一扇门前连拍 10 张，环只亮一小片（证明它不是在数张数）
- [ ] 蹲下拍轮毂，环照样加分；手机几乎平着对地面拍，环不动 —— 这是故意的

> 它看不见车，原地转一圈也会被当成绕了一圈。这是选定的取舍，不是 bug。

### B5a. ⭐ 照片是不是相机自己写的、方向对不对

齿轮 →「相机」。

- [ ] 拍一张，「上一张照片」显示 **3024×4032**（1× 默认 1200 万）
- [ ] 文件拿回电脑，`sips -g pixelWidth -g pixelHeight` 对得上，**而且照片是竖的**
- [ ] 后台或导出的 manifest 里 `metadataPath` 是 **`writtenAtCapture`**（不是 `encodedFromCameraPixels`）
- [ ] 切到 0.5× 拍一张，也是竖的，尺寸记一下：________
- [ ] 打开「4800 万像素」（只有支持的手机才有这个开关），1× 拍一张：________（应该是 6048×8064）
- [ ] 1200 万和 4800 万各一张，单张多少 MB？________ / ________

> 如果照片是横躺着的，说明方向标签没写对 —— 记下来，这是这一版最容易出的错。

### B5b. 车牌认得出来吗

开头不问车牌了，是从照片里认的。

- [ ] 交单页上车牌那一栏**自动填好了**
- [ ] 填的对不对？________
- [ ] 认错或者没认出来时，能直接改 / 填

> 认车牌至少要拍到两次一致才会自动填（一次误读会输给四次一致的）。
> 如果总是空的，说明 OCR 在你们的车牌上不好使，这条要记下来。

### B5c. ⭐ 11 步计划和镂空线稿 —— 这一版的主要改动

整个引导流程换了。**没有任何一步需要先点一下再拍**：线稿说拍什么，按快门就行。

- [ ] 打开就是第 1 步「环绕一圈」，中间浮着一辆车 + 一圈地面的线稿
- [ ] 线稿是**半透明镂空**的，看得见后面的车；白车和暗处都还看得清
- [ ] 拍够 20 张就自己跳到第 2 步「保险杠四角」—— **不管环满没满**
- [ ] 每一步的线稿都能一眼看懂是什么（十一张线稿：[Tools/step-outlines.png](Tools/step-outlines.png)）
- [ ] 取景框下面那排点：拍满的是实心，当前那颗有黄圈
- [ ] 按左右箭头能跳到任何一步，跳过的步骤**不会拦着交单**
- [ ] 手动跳到某一步，拍满之后自动交回计划（不会一直卡在那一步）
- [ ] ⭐ **拍了第一张，右下角就出现「完成」**；点进去，交单页列出还差哪几步，写着「不拍也能交单」

逐步核对（每一步的线稿对不对得上要拍的东西）：

- [ ] 1 环绕一圈 20 张 ・ [ ] 2 保险杠四角 4 张 ・ [ ] 3 四条轮胎 4 张
- [ ] 4 车顶前后 4 张 ・ [ ] 5 挡风玻璃 1 张 ・ [ ] 6 后排座椅 1 张
- [ ] 7 前排座椅 1 张 ・ [ ] 8 中控台 1 张 ・ [ ] 9 仪表盘 1 张
- [ ] 10 车内顶棚 1 张 ・ [ ] 11 地毯和门板 3 张

⭐ **第 4 步「车顶前后」要专门盯一下。** 旧版把车顶做成几何判据，
RAV4 上怎么拍都不涨。现在它只数张数：

- [ ] 在一台 SUV 上，举高手机拍 4 张车顶，第 4 步直接过
- [ ] 全程没有任何一处提示「车顶还差」之后又不给办法

⭐ **这一版不应该出现任何一句「这张里看不到车」。** 那道闸跟着 ARKit 一起拿掉了。

- [ ] 对着地面按一张 → **没有任何报错**，照片照常存（只是环不加分）

### B6. 举高手拍车顶

⚠️ **语音和震动引导还没写。** 举高手机的时候屏幕是看不见的。

## D. 交付路径 —— 这段我们只能验一半

### D1. 相册那份

照片是**边拍边存**的，不是交单时才存。所以这一段要在**停车场就验**，不是回电脑再验。

- [ ] 第一次打开 App 时弹了相册权限，点了「允许访问所有照片」
- [ ] **拍第一张之后立刻退到系统相册看** —— 那张已经在里面了
- [ ] 相簿名字是「Walkaround 月日 时:分」
- [ ] 在 Photos 里打开那张，往上滑：**有地图，有时间** —— GPS 没丢
- [ ] 取景框上**没有**挂「这台手机的相册会重新编码照片」这条黄条
- [ ] 故意拍一张糊的（不过闸的），它**也**在相册里 —— 不该因为没过闸就丢掉
- [ ] 拍到一半直接杀掉 App，再打开系统相册：**已拍的全在**

交单页：

- [ ] 填好车牌后点「按车牌命名相簿，核对每一张」
- [ ] 相簿名字变成「车牌 还车 月日」
- [ ] 结果显示「读回来字节完全一致」，张数和拍的张数对得上
- [ ] 相册里**没有重复** —— 补漏是补漏，不是再存一遍

> ⚠️ 如果显示「相册改动了照片」，**这台手机的相册会重新编码**，
> 那条路就不能用来交单，必须改成从后台下载原件、在电脑上用 Turo 网页提交。

> ⚠️ **我们管不到的一段：** 从相册往 Turo 传的时候，如果 Turo App 只拿到
> 「部分照片」权限，iOS 可能在交给它之前把 GPS 抹掉 —— 这是系统行为，
> 不是我们的文件有问题。**给 Turo App 开「所有照片」权限。**
> 传完之后在 Turo 那边点开看一眼有没有位置，能看就说明这条路通。

### D2. 路径自检

- [ ] 右上角齿轮 →「路径自检」→ 从相册选刚才那张
- [ ] 结果是绿色「这条路可以走」
- [ ] **注意看选图器底部那个「包含位置」开关是不是开着的**

> ⚠️ 这个开关用户能关，关了位置就没了，**界面上不会有任何提示**。
> 换手机、升系统之后要重验一次。

### D3. ⚠️ 这一步我们看不见
