# 真机验证清单

到目前为止所有东西验的都是**逻辑、失败路径和模拟器**。相机、AR、相册、上传，
一行都没在真机上跑过。这份清单是把那道门推开。

> **如果只做一件事**，做 §B1：真机拍一张，把文件拷回电脑，跑
> `npx tsx scripts/check-inspection-evidence.ts <文件>`。
> 这一条过了，整条证据链才算真的通；不过，后面全部白搭。

---

## A. 在电脑前（不用车，20 分钟）

### A1. 装到手机上 —— 先别走 TestFlight

第一次验证**直接从 Xcode 跑到自己手机上**。TestFlight 是给员工铺开用的，
每次构建要等审核排队，改一行等十分钟，验不动。

```bash
cd inspection-ios-app && xcodegen generate && open TatoEvidence.xcodeproj
```

Xcode 里：选 target → Signing & Capabilities → 勾 Automatically manage signing →
Team 选你的开发者账号。`co.tatocar.evidence` 这个 Bundle ID 还没注册过，
Xcode 会自己去建。插上手机，选它当运行目标，⌘R。

- [ ] App 装上了，能打开到「车况存证」首页

⚠️ 真机第一次跑会弹「不受信任的开发者」——手机上
设置 → 通用 → VPN与设备管理 → 信任你的开发者证书。

### A2. 权限文案

开一单，进拍摄页，三个权限弹窗会依次出现。

- [ ] 相机权限文案是中文/英文里说得通的话，不是占位符
- [ ] 定位权限说的是「照片要记录位置，保险理赔会拒收没有位置的照片」
- [ ] 相册权限（到汇总页导出时才弹）

## B. 停车场，一台车，一次跑完（60–90 分钟）

停车场这一趟很贵，别分两次。下面每一条都要**当场记下来**，
回电脑前再看就想不起细节了。

### B1. ⭐ 证据链 —— 唯一真正要紧的一条

随便拍一张（哪一格都行）。然后把文件拿回电脑：

**取文件的两种办法**
- Xcode → Window → Devices and Simulators → 选手机 → 找到 TATO Evidence →
  齿轮 → Download Container → 右键「显示包内容」→
  `AppData/Library/Application Support/sessions/<批次>/photos/`
- 或者到汇总页「存进相册」，再从 Mac 的「照片」App 里导出原件（**必须选"未修改的原始文件"**）

```bash
npx tsx scripts/check-inspection-evidence.ts ~/Downloads/front-1.jpg
```

要看到：

- [ ] `capture` 有值，带时区（形如 `2026:09:19 14:03:21 -07:00`）
- [ ] `location` 有经纬度，不是 `-`
- [ ] `camera` 是 `Apple iPhone 1X Pro`
- [ ] 三条 `PASS`

同时在 App 的汇总页看这一张的记录：

- [ ] `metadataPath` 是 **`writtenAtCapture`**

> ⚠️ 如果是 `stampedAfterCapture`，说明 AVFoundation 没把元数据写进去，
> 走了 `ExifStamper` 回退。**不算坏**（回退路径是有测试的），
> 但如果**每一张**都在回退，那主路径在这个 iOS 版本上是失效的，要查。

**还要确认没拿到占位图**（iOS 17+ 的 deferred photo proxy）：

- [ ] 文件大小是 1MB 以上的量级，不是几十 KB
- [ ] 用「预览」打开是完整清晰的照片，不是糊的缩略图

### B2. ⚠️ 量一下一次绕车到底多大

这条可能会逼我们改设计。相机现在设的是**这台手机支持的最大分辨率**，
iPhone Pro 上就是 4800 万像素。

拍满 24 张，然后：

- [ ] 单张多少 MB？________
- [ ] 一个批次总共多少 MB？________

> 算笔账：如果单张 8MB，一次绕车就是 **190MB**；一单行程交车+还车两次 = **400MB**；
> 一天十单就是 **4GB/天**。
>
> `lib/uploads.ts` 的注释里写着，他们的 Railway 卷**已经被填满过一次，网站挂了**。
>
> 如果数字大得离谱，就把 `EvidenceCamera` 里的 `maxPhotoDimensions` 从"最大"
> 改成 1200 万像素 —— 存证要的是看得清刮痕，不是数毛。Turo 官方 App 拍的也就这个量级。
> **这个决定要基于量出来的数字，不是猜。**

### B3. 清晰度闸 —— 现在只能看行为，不能定阈值

- [ ] 故意晃着拍一张 → 弹「糊了」，能重拍
- [ ] 好好拍一张 → 直接过
- [ ] 连拍 3 张糊的 → 出现「仍然使用」
- [ ] 点了「仍然使用」→ 汇总页那一格显示手动放行的标记

⚠️ **别在这一步调阈值。** `ImageQualityThresholds.provisional` 里的数是占位的，
要靠 §E 的样本标定。这里只确认闸门本身在工作。

### B4. 定位

- [ ] 室外：黄条「定位未就绪」几秒后消失
- [ ] 关掉定位权限再拍一张 → 照片**照样存下来**，汇总页标「缺位置」
- [ ] 地下车库（如果有）：黄条一直在，但能继续拍完

### B5. 绕车覆盖 —— 最不确定的部分

先看这台手机被判成哪一档:

- [ ] 界面出现「识别车辆」按钮 → LiDAR 路线（Pro 机）
- [ ] 界面出现「我在车头 / 我在车尾」→ VIO 路线（标准版）

**LiDAR 路线：**
- [ ] 举着手机绕车走半圈，点「识别车辆」
- [ ] 认出来了吗？还是报「扫到的东西不像一台车」？
- [ ] 认出来之后，走到「左前 45°」，界面是不是说「位置对了」？
- [ ] 16 个外观机位挨个走一遍，有几个匹配不上？________ 哪几个？________
- [ ] 绕完一整圈回到起点，位置还准吗？（VIO 漂移）

**必须试三种车况**，三种表现可能完全不同：
- [ ] 白车 / 浅色车
- [ ] **黑车**（黑漆对红外是镜面，网格会有洞）
- [ ] **强阳光下**（红外被阳光淹没，重建会退化）

**VIO 路线（找一台标准版 iPhone 试）：**
- [ ] 贴着前保险杠点「我在车头」，走到车尾点「我在车尾」
- [ ] 标定成功了吗？还是报「这两个点对不上一台车」？

⚠️ 还有两组数只能在真车上定：`VehicleFrameFitter.bodyHeightRange`（0.25–2.2m）
和 `VehicleFrame.isPlausible`（长 3.0–6.5m、宽 1.4–2.4m）。
**皮卡、带车顶架的车、七座 MPV 很可能被判成「不像一台车」**。
试一台你们车队里最大和最小的车。

- [ ] 最大的车：________ 认出来了吗？
- [ ] 最小的车：________ 认出来了吗？

### B6. 车顶那一格

⚠️ **语音和震动引导还没写。** 设计里 `handsFree` 这个标记有了，
但真正的语音播报和触觉反馈**没有实现** —— 这一格现在和别的格一样，只有屏幕。

- [ ] 举手过头拍车顶，看不见屏幕的情况下能不能拍成？
- [ ] 如果很难，这就是下一个要做的功能

## C. 回到电脑前（30 分钟）

### C1. 上传

在 App 的「上传设置」里填 `http://<你 Mac 的局域网 IP>:3000` 和工号，
Mac 上 `npm run dev`（或者直接填生产地址）。

- [ ] 汇总页「传一份到后台」→ 进度走完
- [ ] 后台 `/inspections` 看得到这一单
- [ ] 点进去，24 格照片都在，能看、能下原件
- [ ] **中途关掉飞行模式再打开** → 重新点上传，是从断点继续而不是从头来

### C2. 后台复核对不对得上

```bash
sqlite3 prisma/dev.db "select slotId, localCaptureTime, utcOffset, latitude, evidenceGaps, clockSkewSeconds from InspectionShot order by createdAt desc limit 5;"
```

- [ ] 服务端自己读出来的时间/位置，和 App 里显示的一致
- [ ] `clockSkewSeconds` 是个小数字（几秒），不是几千

## D. 交付路径 —— 这段我们只能验一半

### D1. 存进相册

- [ ] 汇总页「存进相册，交给 Turo App」
- [ ] 结果显示「读回来字节完全一致」

> ⚠️ 如果显示「相册改动了照片」，**这台手机的相册会重新编码**，
> 那条路就不能用来交单，必须改成从后台下载原件、在电脑上用 Turo 网页提交。

### D2. 路径自检

- [ ] 首页 →「路径自检」→ 从相册选刚才那张
- [ ] 结果是绿色「这条路可以走」
- [ ] **注意看选图器底部那个「包含位置」开关是不是开着的**

> ⚠️ 这个开关用户能关，关了位置就没了，**界面上不会有任何提示**。
> 换手机、升系统之后要重验一次。

### D3. ⚠️ 这一步我们看不见

打开 Turo App，从相簿里选照片提交。

**到这里为止我们的验证就结束了。** Turo 的 App 拿到文件之后怎么处理 ——
会不会转码、会不会剥元数据 —— 我们看不见，也没法测。

唯一的定论只能来自：**真的提交一次索赔，看 Turo 认不认。**

- [ ] 下一次真有损伤要报的时候，用这套流程走一遍，记下结果

## E. 阈值标定（单独一趟，可以晚点做）

清晰度阈值现在是占位的，标定之前**不要让员工依赖那个闸门**。

1. 让员工用平时那套操作，在真实场地拍 50–100 张，**糊的清楚的都要**
2. 人工标注每张「能用 / 不能用」
3. 跑 `ImageQualityGate` 收分数，找分界
4. **往严了压** —— 误判成糊只损失一次重拍，漏判一张糊的要赔一次车

- [ ] 样本收齐了（张数：____）
- [ ] 阈值改过了，并在真机上重新验过 §B3
